# make-knowledge-cards（知识卡片生成器）[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](https://opensource.org/licenses/MIT)  将文章、笔记或学习材料自动转换为结构化的知识卡片，帮助用户高效提取核心内容、快速复习和巩固记忆。  ---  ## 目录  - [项目解决什么问题](#项目解决什么问题)  - [主要功能](#主要功能)  - [安装方法](#安装方法)  - [使用方法](#使用方法)  - [输入输出示例](#输入输出示例)  - [项目结构](#项目结构)  - [测试覆盖](#测试覆盖)  - [限制与说明](#限制与说明)  - [许可证](#许可证)  ---  ## 项目解决什么问题  在日常学习和工作中，我们常常会遇到这样的问题：  - 阅读了一篇长文或技术文档，但难以快速抓住核心要点  - 笔记内容杂乱，复习时效率低下  - 需要为考试或面试准备知识点，但手动整理耗时费力  **make-knowledge-cards** 通过 AI 自动分析文本内容，将冗长的文章或笔记提炼为结构清晰、知识点独立的知识卡片，让学习更有针对性，复习更加高效。  ---  ## 主要功能  - **智能提取**：从用户粘贴的文本或本地 `.md`/`.txt` 文件中识别核心知识点  - **结构化输出**：每张卡片包含标题、核心知识、简明解释、例子或自测问题  - **数量灵活**：根据内容深度生成 5-8 张卡片，内容不足时不强行凑数  - **单点聚焦**：一张卡片只讲一个知识点，删除重复或高度相似的内容  - **忠实原文**：严格基于原文内容，不编造信息  - **语言一致**：输出语言与用户输入保持一致  ---  ## 安装方法  本项目是一个 **Kimi Agent Skill**，安装步骤如下：  ### 1. 克隆或下载项目  ```bash  git clone https://github.com/your-username/make-knowledge-cards.git  cd make-knowledge-cards  ```  ### 2. 部署到 Kimi Skills 目录  将项目文件夹复制到 Kimi 的 skills 目录下：  ```bash  cp -r skills/make-knowledge-cards ~/.config/kimi/skills/  ```  > 注意：具体的 skills 目录路径可能因 Kimi 版本或操作系统而异，请根据实际情况调整。  ### 3. 验证安装  在 Kimi 中加载该 skill 后，输入以下提示词测试：  ```  请帮我将这篇文章转换成知识卡片  ```  如果看到知识卡片生成器的响应，说明安装成功。  ---  ## 使用方法  ### 方式一：直接粘贴文本  1. 向 Kimi 发送提示词，例如：  ```  请帮我将这篇文章转换成知识卡片  ```  2. 粘贴你想要转换的文章或笔记内容  3. Kimi 将自动分析并输出 Markdown 格式的知识卡片  ### 方式二：提供本地文件路径  1. 准备好本地的 `.md` 或 `.txt` 文件  2. 向 Kimi 发送提示词并提供文件路径，例如：  ```  请将 /path/to/your/notes.md 转换成知识卡片  ```  3. Kimi 将读取文件内容并生成知识卡片  ### 提示词示例  | 场景 | 提示词 |  |------|--------|  | 转换文章 | `请帮我将这篇文章转换成知识卡片` |  | 转换笔记文件 | `请将我的笔记文件 /path/to/notes.md 转换成知识卡片` |  | 提取知识点 | `请从以下内容中提取核心知识点，生成学习卡片` |  | 复习备考 | `请帮我把这篇复习材料整理成知识卡片，方便记忆` |  ---  ## 输入输出示例  ### 示例 1：生物学短文  **输入**：  ```  光合作用是指绿色植物利用光能，把二氧化碳和水转化成储存能量的有机物，  并且释放出氧气的过程。光合作用分为光反应和暗反应两个阶段。  光反应在类囊体薄膜上进行，需要光，产生 ATP 和 NADPH。  暗反应在叶绿体基质中进行，不需要光，利用 ATP 和 NADPH 将 CO2 固定并还原为糖类。  ```  **输出**：  ```markdown  ### 卡片 1：光合作用的定义  - **核心知识**：绿色植物利用光能将 CO₂ 和 H₂O 转化为有机物并释放 O₂ 的过程  - **简明解释**：光合作用是植物制造有机物的基础代谢过程，为地球生命提供能量和氧气来源  - **例子/自测**：为什么光合作用对地球生态系统至关重要？（答：它提供了几乎所有生物所需的能量和氧气）  ### 卡片 2：光反应  - **核心知识**：光合作用第一阶段，在类囊体薄膜上进行，需要光照  - **简明解释**：光反应将光能转化为化学能，生成 ATP 和 NADPH，为暗反应提供能量和还原剂  - **例子/自测**：光反应的产物是什么？（答：ATP 和 NADPH）  ### 卡片 3：暗反应  - **核心知识**：光合作用第二阶段，在叶绿体基质中进行，不直接需要光  - **简明解释**：暗反应利用光反应产生的 ATP 和 NADPH，将二氧化碳固定并还原为糖类等有机物  - **例子/自测**：如果光反应停止，暗反应能否长期进行？（答：不能，因为暗反应依赖光反应提供的 ATP 和 NADPH）  ```  ### 示例 2：技术概念  **输入**：  ```  REST（Representational State Transfer）是一种软件架构风格。它由 Roy Fielding 于 2000 年提出。  REST 的核心原则包括：无状态通信，每个请求包含所有必要信息；统一接口，使用标准 HTTP 方法（GET、POST、PUT、DELETE）；  资源标识，通过 URI 唯一标识资源。RESTful API 是目前 Web 服务的主流设计方式。  ```  **输出**：  ```markdown  ### 卡片 1：REST 的定义  - **核心知识**：REST 是一种由 Roy Fielding 于 2000 年提出的软件架构风格  - **简明解释**：REST 定义了一组设计网络应用程序的约束条件和原则，是目前 Web 服务的主流架构方式  - **例子/自测**：REST 是谁在什么时候提出的？（答：Roy Fielding，2000 年）  ### 卡片 2：无状态通信  - **核心知识**：每个请求必须包含理解该请求所需的所有信息，服务器不存储客户端上下文  - **简明解释**：无状态设计简化了服务器实现，提高了系统的可扩展性和可靠性，因为任何服务器都可以处理任何请求  - **例子/自测**：REST 的无状态特性对系统扩展有什么好处？（答：任何服务器实例都可以独立处理请求，便于水平扩展）  ### 卡片 3：统一接口  - **核心知识**：REST 使用标准 HTTP 方法（GET、POST、PUT、DELETE）操作资源  - **简明解释**：统一接口降低了学习成本，使不同系统之间的交互更加标准化和可预测  - **例子/自测**：RESTful API 中 GET 和 POST 的典型用途分别是什么？（答：GET 用于获取资源，POST 用于创建资源）  ### 卡片 4：资源标识  - **核心知识**：通过 URI 唯一标识和定位资源  - **简明解释**：每个资源都有唯一的地址，客户端可以通过 URI 直接访问和操作特定资源  - **例子/自测**：为什么 URI 设计对 RESTful API 很重要？（答：URI 是资源的唯一标识，良好的 URI 设计应直观反映资源层次结构）  ```  ### 示例 3：超短文（内容不足时不强行凑数）  **输入**：  ```  Docker 是一个开源的容器化平台。  ```  **输出**：  ```markdown  ### 卡片 1：Docker 的定义  - **核心知识**：Docker 是一个开源的容器化平台  - **简明解释**：容器化技术允许开发者将应用及其依赖打包在一起，实现跨环境的一致部署和运行  - **例子/自测**：Docker 容器与传统虚拟机的主要区别是什么？（答：容器共享主机操作系统内核，启动更快、资源占用更少）  ```  ---  ## 项目结构  ```  make-knowledge-cards/  ├── README.md  └── skills/  └── make-knowledge-cards/  ├── SKILL.md          # Skill 定义文件（触发条件、工作流程、质量原则）  └── agents/  └── openai.yaml     # Agent 配置（显示名称、默认提示词）  ```  ---  ## 测试覆盖  | 测试类型 | 输入特点 | 预期卡片数 | 结果 |  |---------|---------|-----------|------|  | 生物学短文 | 3 个独立知识点 | 3 张 | ✅ 通过 |  | 技术概念 | 5~6 个知识点 | 4 张 | ✅ 通过 |  | 超短文 | 1 个知识点 | 1 张（不强行凑数） | ✅ 通过 |  | 历史文章 | 4 个主题块 | 5 张 | ✅ 通过 |  ---  ## 限制与说明  当前版本暂不支持以下功能：  | 功能 | 说明 | 替代方案 |  |------|------|---------|  | 网页抓取 | 暂不支持自动抓取网页内容 | 请粘贴文章内容或提供本地文件 |  | PDF 文件 | 暂不支持 PDF 格式直接读取 | 请提取文本后粘贴，或转换为 `.md`/`.txt` |  | Anki 导出 | 暂不支持 Anki 格式导出 | 当前输出为 Markdown 文本，可手动导入 Anki |  | 图形界面 | 暂不提供 GUI | 通过 Kimi 对话界面交互 |  ---  ## 许可证  [MIT](https://opensource.org/licenses/MIT)  Copyright (c) 2026 make-knowledge-cards
